Teach4Free - Pending Setup Notes
================================

Google login configuration
--------------------------

Google login is optional. The application continues to work with email and password when Google credentials are not configured.

Local setup:

1. Create OAuth credentials in Google Cloud Console.
2. Add this authorized redirect URI:

- http://127.0.0.1:8000/auth/google/callback

3. Set these environment variables in the local .env file:

- GOOGLE_CLIENT_ID=
- GOOGLE_CLIENT_SECRET=
- GOOGLE_REDIRECT_URI=http://127.0.0.1:8000/auth/google/callback

Production setup:

1. Add the production redirect URI in Google Cloud Console:

- https://your-domain.com/auth/google/callback

2. Set the production environment variables:

- GOOGLE_CLIENT_ID
- GOOGLE_CLIENT_SECRET
- GOOGLE_REDIRECT_URI

3. Ensure the production site uses HTTPS.

Security notes:

- Do not commit real Google credentials.
- Do not create admin accounts through Google login.
- Do not store Google access tokens unless a future feature explicitly needs them.

Implemented - Internal messaging / chat first version
-----------------------------------------------------

Teach4Free is a contact platform between learners and teachers, so internal messaging is a core feature.

The first messaging version is implemented as a solid internal inbox system, not real-time chat yet.

Implemented first version:

- Internal inbox.
- Conversation list.
- Conversation detail.
- Messages between users.
- Conversations linked to:
  - teaching offer applications
  - teaching offers
  - class sessions
- Unread/read status.
- Unread message count in the navbar.
- Internal notification when a new message arrives.
- Optional external email notification when the user allows message emails.
- User can report a conversation or message.
- Admin can review reported conversations/messages.
- Messages must not expose user emails publicly.
- Conversations should respect platform safety and no-money rules.
- Teachers and students should be able to coordinate without leaving the platform.
- Discreet message action menu with reply, copy and report where appropriate.
- Conversation-level reporting through the conversation header action menu.
- Opening a conversation marks it read for the current participant.
- Admin sidebar/dashboard badges for open incidents and open conversation reports.
